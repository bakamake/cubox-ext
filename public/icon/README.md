# 图标生成说明（public/icon/）

本目录内 `16.png` / `32.png` / `48.png` / `128.png` 由
`tools/gen_icon.py` 从 `assets/cubox_logo_src.png`（Cubox 官方 pricing 页
logo，144×145）自动生成。**禁止手改 PNG**，一切调整改生成器后重跑：

```bash
python3 tools/gen_icon.py
```

配色推导、渲染算法与数学推导见同目录 `MATH.md`。

## 问题与需求

源图是一张 app 图标位图，直接缩放使用存在以下问题：

1. 自带亮蓝色圆角方形底板，缩到小尺寸后与吉祥物本体糊成一团；
2. 位图含渐变与抗锯齿边缘，直接重采样会产生振铃（rimging），在相邻
   高明度差色块之间形成黑/白色缝隙；
3. 风格与 Material You 不符。

需求：生成 Material You（Monet 色彩系统）风格的扩展图标——单色相
tonal 阶梯取色、扁平色块、圆角容器，四档尺寸，零手工修图。

## 源图语义结构（实测采样结论）

| 区域 | 色度特征 | 处置 |
| --- | --- | --- |
| 底板 | 亮蓝圆角方板，lum 0.33~0.60，b−r > 0.30 | 判为背景剔除 |
| 身体 | 深藏青，lum≈0.10 | ramp 低明度档（tone 40） |
| 皇冠 | 亮黄，lum≈0.65 | ramp 高明度档（tone 70），色相归一到 ramp |
| 眼白 | 高亮低饱和纯白 | 纯白 |
| 瞳孔 | 眼白内部的暗像素（lum < 0.35） | ramp 暗端（tone 15） |

注意：几何 flood fill 剔除底板不可行——身体横向延伸至画布左右边缘，
与画布边界相接。底板判定必须使用色度判据。

## 方案演进（修改思路）

1. **硬阈值分区 + 源图色相直出**：按色相/饱和度分身体、皇冠、眼白、
   瞳孔四区。问题：源图渐变边缘被阈值切成色差很大的独立色块，缩放后
   缝隙明显。
2. **硬分区 + 双色相 ramp + 投票渲染**：引入 LCh 色彩空间算法生成
   tonal 阶梯，渲染端按超采样标签投票取主导色（消除振铃缝隙）。剩余
   问题：身体与皇冠各走一条色相 ramp（皇冠曾锁定为琥珀互补色），相邻
   色块色相差过大，仍显脏；且底板混入皇冠类造成琥珀色块污染。
3. **单色相 tonal 量化（当前方案）**：废弃互补双色相。所有实体像素
   按亮度归一化映射到同一 Monet ramp 的不同明度档——身体暗 → 低
   tone，皇冠亮 → 高 tone，源图渐变边缘自然落到相邻明度档，缝隙从
   根因消除。底板按色度判据剔除，眼白保留最大两个连通域防高光散斑。
4. **暗部色值匹配（当前）**：眼周暗描线与瞳孔原压至明度轴端点
   tone 15（近黑），与纯白眼白相邻形成硬描线。第二遍色值匹配将暗部
   提到 tone 30——仍为全场最暗档保住瞳孔辨识，但断开白与近黑的直接
   相邻，眼睛与身体平滑衔接。

## 当前管线

底板剔除（色度判据）→ 单色相 tonal 量化（亮度 p2/p98 归一化 + 中位
阈值二分身体/皇冠）→ 众数滤波轮廓清理（等效形态学开/闭）→ 标签投票
渲染（超采样 1024 母版，覆盖率进 alpha，专杀振铃缝隙）→ squircle
容器（28% 圆角）。

种子色取底板亮蓝中位色（高彩度保证 ramp 全档可辨识），全图共用一条
ramp：30 #3A3E8D / 40 #4C53BA / 70 #A7A0FF / 90 #E4DFFF。

## 打包

图标更新后需重跑打包链（复用 `.output/key.pem` 保持 crx 签名不变）：

```bash
npx wxt build -b firefox && npx wxt zip -b firefox && npx wxt zip && \
cp .output/cubox-ext-0.1.0-firefox.zip .output/cubox-ext-0.1.0.xpi && \
npx --yes crx pack .output/chrome-mv3 -p .output/key.pem -o .output/cubox-ext-0.1.0.crx
```
